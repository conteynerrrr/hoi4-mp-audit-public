# Настройки HOI4 MP Audit 0.1

[Русский](SETTINGS.md) | [English](SETTINGS.en.md)

Это руководство объясняет, что записывает каждая настройка, как уменьшить журнал и почему некоторые команды могут оставаться с неизвестным источником.

**Нужен готовый вариант? Откройте [PRESETS.md](PRESETS.md): там семь профилей, готовые INI и конфиг автора проекта.** Общая установка и просмотр отчёта описаны в [README.md](README.md).

## 1. Где менять настройки

Логгер читает **`mp_audit.ini` рядом с `hoi4.exe`**. Файл в распакованном архиве или репозитории — шаблон; изменение такого файла не изменяет настройки уже установленного логгера.

```text
Hearts of Iron IV/
├── hoi4.exe
├── version.dll
├── mp_audit.ini       ← активный конфиг
└── mp_audit_logs/
```

- `1` включает настройку, `0` выключает. Используйте числа, а не `true`/`false`.
- `[audit]`, `[storage]`, `[tracking]`, `[commands]` — разные секции. Ключ должен находиться в своей секции.
- Строка с `;` в начале — комментарий и не применяется.
- Для одного ключа оставляйте одно значение; повторяющиеся секции и ключи затрудняют проверку конфига.
- Перед заменой всего INI сохраните свою копию. Пресет заменяет также индивидуальные исключения и путь логов.

### Когда применяется изменение

| Что меняете | Когда действует |
|---|---|
| `Enabled`, фильтры, категории и `[commands]` | Примерно через 2 секунды после сохранения INI |
| Сжатие, размер частей и группировка | После перечитывания INI, для последующей записи/ротации |
| `LogDirectory` | Со следующего запуска игры |
| `TrackCommandOrigins` | Со следующего запуска игры |
| Сам файл `version.dll` | Заменять при закрытой игре, затем запускать заново |

Изменение настроек не переписывает ранее сохранённые команды. Служебная строка `settings_reloaded` подтверждает перечитывание файла. Уже захваченные записи могут дописаться из очереди после переключения.

## 2. Быстрый выбор

| Задача | Что сделать |
|---|---|
| Временно остановить запись команд | `[audit] Enabled=0`; для возврата поставить `1` |
| Убрать распознанные команды ИИ | `TrackCommandOrigins=1` и `SkipEngineAICommands=1` в `[audit]` |
| Видеть команды без найденного отправителя | `[audit] OnlyKnownPlayers=0` |
| Оставить только команды с найденным отправителем | `[audit] OnlyKnownPlayers=1` |
| Записывать перемещения | `[tracking] Movement=1` |
| Записывать фронты и боевые приказы | `[tracking] BattleOrders=1` |
| Убрать выбор ответа в событии | `[commands] CSelectEventOptionCommand=0` |
| Уменьшить повторение общих полей | `[storage] CompactJSON=1` |
| Сжимать завершённые части | `[storage] CompressRotated=1` и `MaxFileMB` больше нуля |
| Сворачивать близкие приказы перемещения | `[storage] GroupMovementBursts=1` |
| Сохранить максимум для короткой проверки | [Диагностический пресет](presets/diagnostic.ini) |

Далее значения «в шаблоне» относятся к поставляемому стандартному `mp_audit.ini`. В готовых пресетах и вашем собственном INI они могут отличаться. Новый стандартный профиль ориентирован на основные удаления и изменение перемещений; семь ключевых классов явно включены в [commands]. Их список находится в [PRESETS.md](PRESETS.md).

## 3. Основные настройки — `[audit]`

### `Enabled` — записывать команды

**В шаблоне: `1`.**

- `1` — выбранные команды проходят остальные фильтры и записываются.
- `0` — новые записи игровых команд не создаются. Удобно для временной паузы.

Этот переключатель управляет журналированием. DLL остаётся загруженной, и служебные сообщения о запуске, смене настроек или ошибках могут появляться. Поставьте `1`, чтобы продолжить запись с прежними категориями и исключениями.

### `TrackCommandOrigins` — наблюдать источник команды

**В шаблоне: `1`. Требует перезапуска.**

- `1` — включаются найденные точки наблюдения путей ИИ, интерфейса хоста и сетевого приёма.
- `0` — команды могут записываться без определения их происхождения этими точками.

`origins_ready` в начале нового лога сообщает об успешной установке. При `origins_unavailable` источник может оставаться неизвестным. Охват неполный: для локального интерфейса сейчас подтверждён путь назначения авиамиссий; другие действия могут иметь `unknown`.

Этот ключ не означает «отслеживать только игроков» и не подтверждает человеческого автора. При выключении наблюдения источников фильтр `SkipEngineAICommands` не сможет исключать команды, которые остались нераспознанными.

### `SkipEngineAICommands` — исключать распознанные команды ИИ

**В шаблоне: `1`.**

- `1` — из лога исключаются записи с подтверждённой меткой `origin_kind=engine_ai`.
- `0` — такие записи сохраняются, если проходят остальные фильтры.

Фильтр учитывает наблюдённый источник, а не название класса, страну, ник или частоту команд. `unknown` не объявляется ИИ. Поэтому даже при значении `1` в журнале могут оставаться команды, происхождение которых пока не установлено.

В старом INI без ключа `SkipEngineAICommands` используется `0`: распознанный ИИ продолжает записываться. В готовых обычных пресетах ключ указан явно.

Для работы распознавания оставляйте `TrackCommandOrigins=1`. Опция меняет только журналирование: сами игровые команды продолжают исполняться.

**Отличие от `AIInternal=0`:** `AIInternal` — категория некоторых классов внутренних команд. ИИ также использует обычные игровые классы, например команды авиамиссий; их исключает именно фильтр происхождения.

### `SkipEmptyUnknownCommands` — пропускать пустую диагностику

**В шаблоне: `1`.**

- `1` — пропускаются неизвестные команды, у которых одновременно нет понятного контекста исполнения, найденного отправителя, ненулевого ID команды/оригинала, объекта, страны, полезных параметров, текста, результата или raw-данных.
- `0` — такие записи сохраняются для диагностики.

Типичный пример: `machine_id=-1`, `command_identity=0`, `original_id=0`, `origin_kind=unknown`, `execution_context=unknown` без дополнительных сведений.

Это не общий запрет всех `unknown`. Неизвестная команда с полезными параметрами может сохраниться. Но при `OnlyKnownPlayers=1` отдельный фильтр отправителей всё равно уберёт запись, если участник не найден.

Периодические строки счётчиков фильтрации не создаются. Итоговые числа могут попасть в уже существующую служебную запись завершения, если журнал был штатно остановлен.

### `OnlyKnownPlayers` — требовать найденного отправителя

**В шаблоне: `0`.**

- `0` — отсутствие найденного участника само по себе не исключает запись.
- `1` — сохраняются только команды, чей ID отправителя удалось сопоставить с ником в текущем списке участников.

Название историческое: точнее смысл «только известные отправители». Это не проверка человека и не замена фильтру ИИ. Команда ИИ может иметь отправителем машину хоста и пройти эту проверку; дальше её может исключить `SkipEngineAICommands`.

| Пример | Что означает |
|---|---|
| Есть ник, источник `unknown` | Отправитель найден, происхождение не определено; запись может сохраниться |
| Есть ник хоста, источник `engine_ai` | Команда распознана как ИИ; ник хоста не означает ручное действие |
| Отправитель не найден, но есть ID объекта | При `OnlyKnownPlayers=0` запись может сохраниться; при `1` будет исключена |

Для более полного разбора оставляйте `0`. Значение `1` уменьшает шум от неназначенных отправителей, но исключает также потенциально полезные записи без сопоставленного участника.

### `IncludeRawPayload` — копировать внутренние байты команды

**В шаблоне: `0`.**

- `0` — raw-данные не добавляются.
- `1` — при доступности памяти сохраняется до 128 байт внутреннего объекта команды в поле `payload_hex`.

Это диагностические данные. Они не равны полному сетевому пакету, названию юнита или готовой расшифровке всех параметров. Настройка увеличивает объём лога; для обычной партии достаточно `0`.

### `CaptureAllCommands` — значение по умолчанию для категорий

**В шаблоне: `0`.**

Это ключ совместимости с предыдущими конфигами. Он определяет исходный выбор для категорий, **которые не заданы явно**.

- `0` — используются обычные значения категорий по умолчанию.
- `1` — незаданные категории считаются включёнными.

Явные `[tracking]` и `[commands]` имеют приоритет. Если написано `Network=0`, значение `CaptureAllCommands=1` не включит сетевые команды. В полном INI, где перечислены все категории, этот ключ практически не меняет их выбор.

Чтобы получить диагностический профиль со всеми категориями, используйте [готовый INI](presets/diagnostic.ini), где каждая категория явно включена.

### `LogDirectory` — папка журналов

**В шаблоне: `mp_audit_logs`. Требует перезапуска.**

Относительный путь отсчитывается от папки с DLL, то есть обычно от папки игры:

```ini
[audit]
LogDirectory=mp_audit_logs
```

Абсолютный путь позволяет вынести журналы в другую папку:

```ini
[audit]
LogDirectory=D:\HOI4_Logs
```

Для вложенного пути заранее создайте родительские папки. При выборе пресета проверьте этот ключ: полная замена INI заменяет и ваш прежний путь логов.

## 4. Что отслеживать — `[tracking]`

Значение `1` выбирает категорию, `0` отключает её. Категории классифицируют типы команд; они не устанавливают автора действия.

| Ключ | Какие команды относятся к категории | В шаблоне |
|---|---|---:|
| `Units` | Юниты, армии, командиры, удаления юнитов, кораблей и авиакрыльев | 1 |
| `Equipment` | Снаряжение, варианты, склад и удаление складского снаряжения | 1 |
| `Production` | Производственные линии, заводы на линиях, приоритеты производства | 1 |
| `Theaters` | Театры: назначение, переименование, перестановка, расформирование | 1 |
| `Construction` | Стройки, здания, конверсия заводов, железные дороги, снабжение | 1 |
| `Templates` | Шаблоны дивизий | 1 |
| `Politics` | Фокусы, исследования, решения, события, доктрины, советники | 0 |
| `Diplomacy` | Дипломатия, торговля, ленд-лиз, фракции, рынок | 0 |
| `Deployment` | Развёртывание и тренировочные очереди | 1 |
| `AirNavy` | Авиация, авиамиссии, флот, морские миссии и рейды | 0 |
| `Movement` | Перемещения, стратегическая передислокация, отмена движения | 1 |
| `BattleOrders` | Фронты, оборона, наступательные и другие боевые приказы | 0 |
| `Network` | Ping, тики, checksum, синхронизация, передача файлов | 0 |
| `AIInternal` | Классы внутренних команд с префиксами `CAi…` / `CAI…` | 0 |
| `Interface` | Команды интерфейса, закреплённые регионы, чат, подсветка | 0 |
| `Other` | Команды, не отнесённые к категориям выше | 0 |

Полное соответствие **конкретного класса** категории смотрите в [command_catalog.csv](command_catalog.csv). Названия игровых действий не всегда однозначно отражают внутренний класс. В каталоге 456 типов, но это не гарантия охвата каждого действия интерфейса или локальных действий клиента.

Перемещения включены в новом стандартном профиле. Боевые приказы выключены по умолчанию; для них включите BattleOrders. Ключевые классы перемещения дополнительно включены через [commands].

## 5. Точные исключения — `[commands]`

Ключ — точное имя из поля `command_class` или каталога. `1` включает класс независимо от категории, `0` исключает его независимо от категории.

```ini
[tracking]
Units=1
Movement=0
Politics=1

[commands]
CMoveCommand=1
CSelectEventOptionCommand=0
```

Результат: основная категория перемещений выключена, но `CMoveCommand` выбран отдельно. Политические команды включены, а выбор ответа в событии исключён.

Ещё примеры:

| Что настроить | Строка в `[commands]` |
|---|---|
| Выбирать команду удаления юнита | `CDeleteUnitCommand=1` |
| Выбирать команду удаления складского снаряжения | `CStockpiledEquipmentDeleteCommand=1` |
| Выбирать удаление производственной линии | `CRemoveProductionLineCommand=1` |
| Исключить назначение авиамиссии | `CStratAirSetMissionCommand=0` |
| Исключить выбор ответа в событии | `CSelectEventOptionCommand=0` |

Чтобы вернуть поведение категории, удалите строку или закомментируйте её `;`. Переключатели класса не отменяют `Enabled=0`, фильтр найденного отправителя, подтверждённого ИИ или пустой диагностики.

### Порядок выбора записи

1. `Enabled` разрешает запись команд.
2. Явное значение в `[commands]` выбирает/исключает класс; иначе используется категория `[tracking]`.
3. Если категория не задана, её исходный выбор зависит от `CaptureAllCommands` и обычных значений по умолчанию.
4. При `OnlyKnownPlayers=1` требуется сопоставленный отправитель.
5. Фильтры `SkipEngineAICommands` и `SkipEmptyUnknownCommands` исключают подходящие записи.
6. Оставшиеся команды сохраняются; подходящие перемещения могут упаковываться в серию.

**Пример:** `CDeleteUnitCommand=1` выбирает класс, но если именно эта команда получила `engine_ai`, при `SkipEngineAICommands=1` она не попадёт в лог.

## 6. Объём и хранение — `[storage]`

| Ключ | В шаблоне | Допустимые значения |
|---|---:|---|
| `CompactJSON` | 1 | 0 / 1 |
| `MaxFileMB` | 4 | 0–64; 0 отключает ротацию |
| `CompressRotated` | 1 | 0 / 1 |
| `GroupMovementBursts` | 1 | 0 / 1 |
| `MovementBurstWindowMs` | 50 | 1–500 мс |

### `CompactJSON` — компактная запись

`1` убирает повторяющиеся, пустые и избыточные поля. Основное время UTC и доступные сведения о команде сохраняются. `0` использует полный JSON с дополнительными диагностическими полями, включая QPC/FILETIME.

Это настройка представления, а не выбора категорий. Компактный JSON не включает/исключает сами типы команд и не меняет raw-копирование.

### `MaxFileMB` — размер одной части

`4` создаёт новую часть примерно при достижении 4 МиБ. Строки JSON не разрываются посередине; размер может немного отличаться. Значения больше 64 ограничиваются 64.

`0` сохраняет текущую сессию без деления по размеру. Это также не даёт обычной ротации создавать части для `CompressRotated`.

**Это не лимит всей истории.** Старые сессии автоматически не удаляются; папка продолжает расти.

### `CompressRotated` — gzip завершённых частей

`1` сжимает завершённую часть после перехода к новой. Сжатие выполняется потоком журнала; игровые команды не ждут архивирования в своём потоке. Формат стандартный `.jsonl.gz`.

Текущий `.jsonl` остаётся открытым для записи. Последняя часть может остаться текстовой и после выхода из игры: автоматическое сжатие привязано к ротации. При ошибке сжатия исходные данные сохраняются.

`0` оставляет части текстовыми. Старые архивы при этом не распаковываются. В этом релизе нет ключей для выбора xz или уровня gzip.

### `GroupMovementBursts` — упаковка близких приказов

`1` упаковывает подходящие подряд идущие команды:

- `CMoveCommand`;
- `CCancelMovementCommand`;
- `CStrategicRedeploymentCommand`.

Нужны тот же отправитель, тип, tickstamp, источник, обычный контекст очереди и совпадающие общие сведения. ИИ, повторы, неоднозначные источники и удаления не упаковываются. Серия ограничена 128 командами.

Все индивидуальные времена, ID, объекты, параметры и raw-данные членов серии сохраняются. Общие сведения записываются один раз. Упаковка уменьшает повторение полей, а не заменяет команды одним счётчиком.

`0` оставляет команды отдельными записями. **Отчёт всё равно может визуально сворачивать близкие приказы:** для раздельных строк отчёта используйте `-ExpandBatches`.

Настройка не включает категорию перемещений. При `Movement=0` и отсутствии точечных включений подходящих команд для упаковки может не быть.

### `MovementBurstWindowMs` — временное окно серии

По умолчанию `50` мс **от первой команды серии**. Это не окно, которое бесконечно продлевается каждым следующим приказом. Значения меньше 1 ограничиваются 1, больше 500 — 500.

Меньшее окно чаще разделяет команды. Большее позволяет собрать более длинную серию, но может объединить несколько быстрых разных приказов. Группировка не является подтверждением одного клика, а количество команд — числом юнитов. Время UTC относится к исполнению, не ко вводу мышью.

## 7. Настройки отчёта отдельно от INI

Эти параметры передаются `scripts/report.ps1` и не записываются в `mp_audit.ini`.

| Параметр | Результат |
|---|---|
| `-LogPath "путь"` | Один `.jsonl`, `.jsonl.gz` или папка журналов |
| `-OutputPath "путь"` | Своё имя итогового HTML/CSV |
| `-Csv` | CSV вместо HTML |
| `-Sender "Nickname"` | Фильтр по нику отправителя, не подтверждённому автору |
| `-ExcludeEngineAI` | Скрыть уже записанные подтверждённые команды ИИ |
| `-IncludeEmptyUnknown` | Вернуть пустые неизвестные записи, которые есть в исходнике |
| `-ExpandBatches` | Показать отдельные команды вместо серий |
| `-MovementBurstWindowMs 50` | Окно визуальной группировки; 1–500 мс |
| `-MaxRows 20000` | Лимит последних записей; по умолчанию 10000, диапазон 1–200000 |

Пример:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\report.ps1 -LogPath "C:\Games\Hearts of Iron IV\mp_audit_logs" -ExcludeEngineAI -ExpandBatches
```

Исходные файлы сохраняются. HTML позволяет раскрывать детали серии. В свёрнутом CSV параметры относятся к первой команде, рядом указаны количество, диапазон времени и все ID; для отдельных параметров каждого события добавьте `-ExpandBatches`.

Отчёт читает обычные записи схем 1/2/3 и серии схемы 4. Фильтр отчёта не может восстановить события, которые DLL вообще не сохранила. При наличии одинаковой текстовой части и её `.gz`-копии в режиме папки используется текстовая копия, чтобы не задваивать данные.

## 8. Частые вопросы

**Включил `CaptureAllCommands=1`, но часть команд не появилась.** Проверьте явные категории, `[commands]` и остальные фильтры. Этот ключ не перекрывает их.

**Включил `SkipEngineAICommands=1`, но вижу команды с `unknown`.** Их источник не установлен. Они не объявляются ИИ и не исключаются по предположению.

**Есть ник хоста — значит он нажал кнопку?** Нет. Это ник машины-отправителя; ИИ может использовать ту же машину. Человеческое авторство отдельно не подтверждено.

**Зачем `OnlyKnownPlayers=0`, если интересуют игроки?** Это сохраняет потенциально полезные события, для которых список участников не дал сопоставления. При `1` их меньше, но пропуски могут затронуть и нужные команды.

**Включил группировку, но в логе много строк.** Группируются только три подходящих типа перемещения. Разные отправители, типы, тики, параметры общих сведений, временные окна и порядок разделяют серии; удаления остаются отдельными.

**Поменял фильтр, а старые строки остались.** INI действует на последующую запись. Для скрытия ранее сохранённого ИИ используйте `-ExcludeEngineAI` в отчёте.

**В архиве есть конфиг, но игра его не использует.** Активный INI должен находиться рядом с используемым `hoi4.exe` и называться именно `mp_audit.ini`.

**Как применить готовый вариант?** Откройте [PRESETS.md](PRESETS.md), сохраните свой INI и замените его выбранным профилем. Для возврата к текущим настройкам автора есть [author-current.ini](presets/author-current.ini).
